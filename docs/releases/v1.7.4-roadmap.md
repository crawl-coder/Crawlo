# Crawlo 1.7.4 Roadmap

> **版本目标**：补齐通用爬虫骨架的 3 项真实短板，让 Crawlo 在「整站抓取 + 长驻运行」场景更成熟。
>
> **前置版本**：1.7.3（已达标发布到 PyPI）
> **目标版本**：1.7.4
> **核心主题**：基于 Crawlo 自身定位（企业级深爬 + 分布式 + 渲染 + 长驻）补齐真实刚需，不为对齐 Scrapy 而强行开发。

---

## 设计原则

1. **需求驱动，不是对表驱动**：每一项必须有真实用户痛点，而非"Scrapy 有所以 Crawlo 也要有"。
2. **不重复造轮子**：Crawlo 已有的能力（Failure.getTraceback / rich 日志 / Prometheus + HealthCheck 运维体系 / filters 去重实现）不重做。
3. **不做过时方案**：Telnet REPL 是 2010 年代的运维手段，现代运维用 Prometheus + Grafana + 结构化日志 + 告警。

## P0-1：LinkExtractor 链接提取器

### 背景

grep `LinkExtractor` 在 `crawlo/` 零命中。整站抓取时用户必须手写 parsel 解析 `<a>` 标签 + urljoin 拼绝对路径 + 自行做 allow/deny 过滤 + 去重，样板代码多且容易出错。

### 目标

发布 `crawlo.contrib.linkextractors.LinkExtractor` 作为**工具函数**（非 CrawlSpider 框架），用户在 parse 回调中按需调用。

### 交付项

1. `LinkExtractor(allow, deny, allow_domains, deny_domains, restrict_css, restrict_xpaths, tags=('a', 'area'), attrs=('href',), unique=True, process_value=None)`
2. `link_extractor.extract_links(response)` 返回 `List[Link]`（url / text / fragment / nofollow）
3. 内置 urljoin 拼绝对路径 + canonicalize + 去重
4. 单元测试 ≥ 15 用例（覆盖 allow/deny 正则、domain 限制、CSS/XPath 限制、unique、空结果、相对路径拼接）
5. 文档 + Cookbook 1 篇「整站抓取」

### 验收标准

- `from crawlo.contrib.linkextractors import LinkExtractor` 可独立使用
- `LinkExtractor(allow=r'/article/\d+').extract_links(response)` 返回过滤后的链接列表

### 不做什么

- **不做 CrawlSpider**：Crawlo 用户在 parse 回调里 `yield Request` 控制 follow 逻辑，不需要声明式 Rule 链

## P0-2：Autothrottle 自适应节流扩展

### 背景

当前只有静态 `DOWNLOAD_DELAY` + `DOWNLOAD_DELAY_OVERRIDES`（[download_delay.py](file:///Users/oscar/projects/Crawlo/crawlo/middleware/download_delay.py)）。深爬大站时：设太高浪费时间，设太低被封 IP。Crawlo 定位长驻运行，自适应节流是生产刚需。

### 目标

发布 `crawlo.extensions.autothrottle.AutoThrottleExtension`，基于实时 latency / pending / 错误率自适应调节并发和延迟。

### 交付项

1. Settings：`AUTOTHROTTLE_ENABLED` / `AUTOTHROTTLE_START_DELAY` / `AUTOTHROTTLE_MAX_DELAY` / `AUTOTHROTTLE_TARGET_CONCURRENCY` / `AUTOTHROTTLE_DEBUG`
2. 信号监听：`response_received(latency_ms, status)` + `request_scheduled(pending_len)` + `engine_inflight`
3. 算法：EWMA 平滑 latency → 目标 concurrency = min(target, target_latency / actual_latency) → 动态调整 `CONCURRENT_REQUESTS_PER_DOMAIN` + delay
4. 5xx / 超时 → 自动降速；2xx 且 latency 低 → 逐步加速
5. `AUTOTHROTTLE_DEBUG=True` 时每 10s 打印 throttle 状态
6. 单元测试 ≥ 10 用例 + 集成测试 1 个（模拟 latency 波动验证收敛）

### 验收标准

- 启用后，目标站点延迟从 2s 波动到 0.5s 时，Crawlo 并发数在 30s 内从 2 上升到 `target_concurrency`
- 5xx 时 5s 内降速到 `max_delay`

## P0-3：JOBDIR 断点续爬

### 背景

`crawlo/filters/` 下已有 `MemoryFilter` + Redis 过滤器实现，但 grep `JOBDIR` 零命中。长驻任务进程崩溃后，已抓的 URL fingerprint 丢失，重启后从头重抓。对跑数天的深爬任务是硬伤。

### 目标

`JOBDIR` setting 统一管理断点续爬：fingerprint + scheduler pending queue 持久化到磁盘目录。

### 交付项

1. `JOBDIR` setting：设置后 fingerprint 持久化到 `{JOBDIR}/requests.seen`，scheduler pending queue 持久化到 `{JOBDIR}/requests.queue`
2. `Ctrl+C` 优雅停止 → 下次启动 `--jobdir=xxx` 继续抓
3. `request.dont_filter=True` 旁路贯通 scheduler → engine → filter（确认现有实现已贯通，补测试）
4. 文档化现有 `DUPEFILTER_CLASS` 入口（`crawlo/filters/` 已有实现，只需在 settings 中公开默认值和可替换说明）
5. 单元测试 ≥ 12 用例 + 集成测试 1 个（启动 → 停止 → 重启验证 0 重抓）

### 验收标准

- 设 `JOBDIR=./jobs/myjob`，抓 100 条后 `Ctrl+C`，重启后 `requests.seen` 已有 100 条 fingerprint，不重抓

### 不做什么

- **不重做 DUPEFILTER_CLASS 协议**：`crawlo/filters/` 已有实现，只需文档化入口

## P1-4：Response 补 `.re()` / `.re_first()` + Selector re-export（零成本顺手做）

### 背景

[Response](file:///Users/oscar/projects/Crawlo/crawlo/http/response.py#L324-L378) 已有 `.css()` + `.xpath()` + 自适应追踪（`adaptive=True`，比 Scrapy 多的能力）。只差 `.re()` / `.re_first()` 方法和顶层 `crawlo.Selector` re-export。

### 交付项

1. `Response.re(regex)` / `Response.re_first(regex)` — 委托给 `parsel.SelectorList.re()`
2. `crawlo.Selector` re-export `parsel.Selector`（在 `crawlo/__init__.py` 的 `__getattr__` 中加一条）
3. 单元测试 ≥ 5 用例

### 验收标准

- `response.css('a::attr(href)').re(r'/article/\d+')` 可用
- `from crawlo import Selector` 可用

## 与 Scrapy 2.12 的能力对比总结

### Crawlo 1.7.3 已超过 Scrapy 的项（1.7.4 保持优势）

- 原生 asyncio 性能（无 Twisted 桥接开销）
- Redis Stream 分布式 + XCLAIM 自动补偿（3 模式：standalone / single_node / multi_node）
- 多爬虫共享连接池 + ResourceScope 泄漏检测 + ObjectCounter
- Playwright / Camoufox / DrissionPage / CloakBrowser 多渲染内核 + stealth 脚本集
- 飞书 / 钉钉 / 企微 / 邮件 / SMS 6 频道监控通知 + Prometheus 后端
- MCP 服务端 + quick_fetcher（AI Agent 直连）
- 6 套 settings 模板（minimal / gentle / 高并发 / 分布式）
- 任务调度（cron-like）+ cluster 命令行一栈到底

### Crawlo 1.7.4 补齐后与 Scrapy 持平的项

- LinkExtractor 链接提取器（P0-1）
- Autothrottle 自适应节流（P0-2）
- JOBDIR 断点续爬（P0-3）
- Response `.re()` + Selector re-export（P1-4，零成本顺手做）

### Crawlo 不追赶 Scrapy 的项（已有更好替代或属于过时方案）

| Scrapy 功能 | Crawlo 现状 | 不追赶理由 |
|---|---|---|
| LogFormatter | rich 结构化日志 | Crawlo 日志风格不同，LogFormatter 是 Scrapy idiom |
| TelnetConsole | Prometheus + HealthCheck + 6 频道通知 | Telnet 是 2010 年代方案，现代运维用指标 + 告警 |
| CrawlSpider | 用户在 parse 回调 `yield Request` | 企业级深爬需要自己控制 follow 逻辑，声明式 Rule 链是多余抽象 |
| Feed Exports | Pipeline 体系（CSV/JSON/MySQL/PG/ClickHouse/Mongo/ES/HBase） | Crawlo 的 Pipeline 比 Scrapy Feed Exports 更强 |
| 15 年社区生态 | — | 生态靠时间积累，1.7.4 不追赶，靠 Cookbook + 文档质量缩小体感差距 |
