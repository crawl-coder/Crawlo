## Overview

v1.7.3 是一次大规模架构重构版本。相比 v1.7.2，框架完成了包结构重组、引擎拆分、异常体系分散化、资源生命周期管理四项核心改造，同时修复了分布式模式下多个关键缺陷。

本次版本**不保证向后兼容**，旧 import 路径已全部删除，升级时需要按下方迁移指南调整。

## Architecture Changes

| `crawlo/core/engine.py` | 580 | 引擎主骨架：生命周期管理、启动/停止流程、信号调度 |
| `crawlo/core/engine_dispatch.py` | 209 | 请求调度：队列选择、优先级计算、空闲检测 |
| `crawlo/core/engine_distributed.py` | 236 | 分布式调度：XCLAIM 扫描、种子锁、协调关闭 |

## New Features

### ResourceScope — 资源作用域管理

新增 `crawlo/core/resource_scope.py`，解决两个生产场景：

**场景 1：多爬虫共享资源**

同一项目内多个爬虫并发运行时共享数据库连接池，所有爬虫结束后统一释放。通过 `shared_resource_scope(tag)` 上下文管理器 + 连接池引用计数实现：

```python
async with shared_resource_scope('batch') as scope:
    tasks = [cp.crawl(spider_name) for _ in range(N)]
    await asyncio.gather(*tasks)
# 所有 crawler.close 完成后，ref_count 归零，共享池自动释放
```

**场景 2：定时任务长期运行**

调度器连续运行数月/数年时，内存和数据库连接数不随时间线性增长。通过以下机制保障：

- **`WeakBound`** — 弱引用包装 `Crawler` 和 `settings`，旧轮次 Crawler 被 GC 后自动返回 None，不阻断回收
- **`ObjectCounter`** — 按 GC 类型累计计数 + 最小二乘斜率计算，检测对象是否线性增长
- **`PoolSnapshot`** — MySQL/Redis/Mongo 连接池实例数与总连接数快照对比
- **`on_iteration_end(tag)`** — 每轮调度结束后推进事件循环、执行 GC 全代回收、对比基线快照检测泄漏

### Pipeline Stub 属性兜底

`crawlo/pipelines/base_pipeline.py` 新增 `_StubStats`、`_StubSettings`、`_StubCrawler`。`crawler` / `settings` / `stats` 三个 property 在资源释放后自动切换到 Stub 对象，保证 close 收尾阶段不抛 `AttributeError`。

### PipelineManager 幂等 close

`crawlo/pipelines/manager.py` 新增 `_closed` 标志，防止 SPIDER_CLOSED 事件回调重入导致的资源提前释放。

### 扩展层弱引用改造

- `crawlo/extensions/monitor/base.py` — `BaseMonitorExtension` 的 `crawler` / `settings` 改为 `WeakBound` property
- `crawlo/extensions/health_check.py` — 子 task 追踪 + cancel + `_safe_log`，确保 logger=None 时不抛错

### EventloopLagProbe

新增 `crawlo/extensions/eventloop_lag.py`，采样事件循环延迟，输出 p50/p95/p99 分位数到 stats。

### 主动 XCLAIM 扫描

分布式模式下，Engine 主动扫描 Redis Stream 的 Pending Entries List，回收超时未确认的消息，避免 Worker 异常退出后消息长期积压。

### RingBuffer 指标

新增 `crawlo/utils/ring_buffer.py`，为 Downloader 和 Pipeline 提供轻量级 p99 延迟采样。`aiohttp_downloader.p99_response_ms` 和 `generic_sql.p99_latency_ms` 直接暴露属性，`LogIntervalExtension` 每 tick 读取写入 stats gauge。

## Bug Fixes

### 队列选择逻辑

- `auto` 模式自动选择 Redis ZSET 而非 Stream
- `distributed` + `QUEUE_TYPE=redis` 时强制升级为 Stream，三种模式完全解耦
- 修复 `_init_cluster` 在 distributed 下 QUEUE_TYPE=redis 的场景兼容性

### Checkpoint

- 默认彻底关闭（`CHECKPOINT_ENABLED=False`、`SAVE_ON_SIGNAL=False`），避免非预期行为
- `JsonStorage` 新增 `filepath` 属性，修复 `CheckpointManager` 的 `AttributeError`
- `resume` 空检查点时不跳过 `start_requests`
- `save` 先提取指纹再提取请求，避免间隙竞态丢失数据

### 分布式协调

- `Coordinator` 10Worker 分布式测试通过，种子锁唯一性 + 协调关闭验证
- `close_spider` 异常时触发 `SPIDER_CLOSED` 事件，确保扩展收到通知

### 空闲检测

- `auto` 模式空闲退出时空队列检测回归正常，不再出现 29 分钟卡死

### 其他

- `metrics_endpoint` 改为 localhost 以方便 curl 使用
- Prometheus 后端并发访问添加 `threading.Lock` 保护
- `from_dict` 对 `path` / `attribs` 为 None 的容错

- 标签名提前校验 + 并发/响应面板改为 Stat 类型
