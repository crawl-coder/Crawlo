# v1.7.4

**Tag:** `v1.7.4`
**Date:** 2026-08-10（规划）
**Previous:** `v1.7.3`

---

## Overview

v1.7.4 是 **1.0 稳定化路线的工程化收口版本**。相比 v1.7.3 的架构重构，
本版本聚焦五件事：**冻结 API 面、建立发布纪律、补齐插件与示例体系、
落地生产验证工具、完成日志与可观测性收口**，为 1.0 发布扫清工程化障碍。

核心主题：从"功能驱动的快速演进"切换到"稳定驱动的 1.0 收口"。

## Breaking Changes

### 移除 `crawlo.bot` 兼容存根

`crawlo.bot`（含 channels/core/monitoring/templates/utils 子包）已在 1.7.4
**提前移除**（原计划 v2.0，项目决策提前），属刻意 breaking change：

```python
# ❌ 1.7.4 起抛 ModuleNotFoundError
from crawlo.bot import get_notifier, ChannelType

# ✅ 唯一合法路径
from crawlo.extensions.notifications import get_notifier, ChannelType
```

> 迁移示例见 [通知指南](../guides/notification-guide.md)。

### Python 版本要求提升至 3.10+

`python_requires` 从 `>=3.8` 提升到 `>=3.10`（代码已使用 3.10+ 类型语法，
CI 矩阵实际覆盖 3.10–3.14）。

## New Features

### 1. API 面冻结（1.0 前置）

- 新增 [api-surface.md](../reference/api-surface.md)：**454 个公共符号**
  100% 覆盖审计，逐项标注 frozen / experimental / optional / internal；
- 兼容性守护扩展：签名守护从 5 个核心类扩展到 **57 类 / 471 个方法**；
- 新增 import-path 兼容矩阵测试（97 个模块路径 + 34 组顶层符号 + shim 迁移等价）；
- **效果**：任何"删符号不改测试"的 PR 会被 CI 直接拦截。

### 2. 发布纪律

- 新增 `crawlo release --dry-run` 发布就绪检查：
  semver 版本号 / CHANGELOG 条目 / 发布说明 / git tag 一致性；
- 新建 `CHANGELOG.md`（Keep a Changelog 格式）+ 发布模板
  `docs/releases/_TEMPLATE.md`；
- CI 新增 release-check 门禁（PR 合入 main + 版本 tag 推送时强制检查）。

### 3. 插件机制（P1）

- 新增 `crawlo.plugin` 统一注册表：
  `register_middleware` / `register_pipeline` / `register_extension`
  （含对应 `unregister_*`）；
- **双通道配置**：注册表短名称 + 完整字符串路径
  （`load_object` 统一解析，路径优先）；
- 官方示例 `examples/plugin_hello_world/` + 开发指南
  [plugin-development.md](../guides/plugin-development.md)。

### 4. 生产示例体系（P2/P3）

- `examples/real_world_catalog/`：整站抓取 cookbook
  （分页 → 详情 → 去重 → JSONL/MySQL 存储 → 监控 → 分布式），
  含本地 mock 站与 CI 冒烟测试；
- `examples/simple_quickstart/`：**23 行 spider** 跑通第一个爬虫
  （与全部示例同网站 ee.ofweek.com）+ 极简 JSONL 管道；
- `docs/guides/when-to-use.md`：场景决策树（什么时候用什么配置）。

### 5. 稳定性与生产验证工具（P4）

- `scripts/stress_run.py`：长跑压测（RSS / 对象泄漏斜率 / 事件循环延迟）；
- `scripts/benchmark/`：Crawlo vs Scrapy 性能基准；
- `scripts/redis_ha/`：Sentinel 故障切换演练（已端到端实测）；
- `scripts/failure_inject.py`：故障注入（redis-down / network-partition 等）；
- 部署文档 6 篇：Docker / Kubernetes / 监控告警 / Redis HA / 代理轮换 /
  升级回滚。

### 6. 日志轮转与分布式 Worker 日志隔离

- `LOG_FILE` 模板默认改为**固定文件名 + 按天轮转**：
  `LOG_FILE_WHEN='midnight'` / `LOG_FILE_BACKUP_COUNT=7` /
  `LOG_FILE_UTF8_BACKUP=True`，`LOG_RETENTION_DAYS` 1 → 7；
  废弃的按大小轮转键（`LOG_MAX_BYTES` / `LOG_BACKUP_COUNT`）不再生效；
- 新增 `SafeTimedRotatingFileHandler`：解决 Windows 下轮转重命名
  **静默失效**（文件被占用时 rename 失败、日志无限增长）——
  改为**可见告警 + 不崩溃 + emit 后 flush 不丢日志**，
  Linux/macOS 只读挂载等极端场景同样兜底；
- 新增 `LOG_FILE_WORKER_ID`：分布式进集群后自动把 worker_id 追加进
  日志文件名（`LogManager.set_file_path` 动态重建 handler），
  多机/多进程场景各 Worker 日志互不覆盖；**默认开启并跟随运行模式**——
  切换 `CrawloConfig.distributed()` 即自动生效，单机无副作用，
  显式设 `LOG_FILE_WORKER_ID=False` 可关闭；
- `examples/` 全部 Crawlo 项目统一为新日志方案（固定文件名 + 轮转 +
  worker_id 注释），清理历史时间戳命名与死配置。

- **调度日志**：`Filtered duplicate request` 降为 debug 级别，关闭时
  打印汇总条数，消除刷屏；
- **测试体系扩展**：日志轮转 45 项单测（全部 when 取值、backupCount
  0/负数/限额、UTF-8 中文轮转、只读目录降级、Windows rename 失败注入、

## Migration Guide

### 1. 通知系统（必须迁移）

所有 `crawlo.bot` 导入迁移到 `crawlo.extensions.notifications.*`：

```python
from crawlo.extensions.notifications import get_notifier, ChannelType
```

### 2. Python 环境

确保运行环境 Python ≥ 3.10（3.10–3.14 已适配）。

### 3. 日志配置（建议项，非破坏）

- 新项目模板默认**固定日志文件名 + 按天轮转**；旧项目继续使用带时间戳
  文件名不受影响（如需每次启动独立文件，可显式用时间戳命名）；
- 分布式模式日志文件名**自动追加 `worker_id`**，无需任何配置；
  如需关闭：`LOG_FILE_WORKER_ID = False`；
- 旧配置 `LOG_MAX_BYTES` / `LOG_BACKUP_COUNT`（按大小轮转）已不生效，
  迁移到 `LOG_FILE_WHEN` / `LOG_FILE_BACKUP_COUNT`。

### 4. 无其他破坏性变更

1.7.4 除上述两项（bot 移除、Python 版本）外**无 API 破坏**——
其余新增均为向后兼容。

## Known Limitations（已知限制）

以下为分布式设计的已知取舍，1.7.4 保留现状，1.0 后视需求评估改进：

### 1. 单 Consumer Group 模型（无分区/顺序保证）

所有 Worker 竞争同一消费组，任务**无分区、无顺序保证**。爬虫场景够用
（任务间无强依赖），但同一域名的请求顺序无法保证——对站点友好性有
影响，由 `DOWNLOAD_DELAY` 兜底。

### 2. 投递语义为 at-least-once（需去重兜底）

XACK 前崩溃 → XCLAIM 重投 → 下游可能重复写入。当前由
`RedisDedupPipeline` 兜底，且语义已文档化——业务侧需理解
**"at-least-once + 去重"**，幂等性不在框架层保证。完整说明
（重复场景 + 幂等保障建议）见
[分布式投递语义](../concepts/distributed-reliability.md#投递语义at-least-once至少一次)。

### 3. 死信无自动重放

DLQ 只能手动 `crawlo dead-letter retry`，无定时重放策略。偶发失败场景
够用；高频失败场景需外部编排（如定时任务扫描死信重试）。

### 4. 优先级仅双档

高/普通两个 Stream（`priority < 0` 走高优），无多级优先级队列。
爬虫场景可接受。

> 注：此前"pending/lag 未暴露为 Prometheus 指标"的缺口已在 1.7.4
> 落地（`crawlo_queue_pending_count` Gauge），不再属于已知限制。
