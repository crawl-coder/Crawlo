# 代理池与轮换部署指南

> 面向生产：代理池怎么接、怎么保持健康、怎么控制成本。
> 中间件基础配置见 [代理配置](../guides/proxy-guide.md)，本文是运维视角的配套。

## 1. 两种代理模式

### 1.1 静态代理（`PROXY_LIST`）

```python
PROXY_LIST = [
 "http://user:pass@proxy1.example.com:8080",
 "http://user:pass@proxy2.example.com:8080",
]
```

中间件随机选取、自动剔除失败项、全挂时降级直连。适合：

- 代理数量少（几十个以内）；
- 代理由固定供应商提供、无需动态调配；
- 只需要"换 IP 分散请求"的轻量反爬场景。

### 1.2 动态代理 API（`PROXY_API_URL`）

```python
PROXY_API_URL = "https://api.proxy-supplier.com/get"
PROXY_EXTRACTOR = {"type": "jsonpath", "value": "$.data[0].proxy"}
PROXY_MAX_FAILED_ATTEMPTS = 3
```

每次请求从外部 API 拉取代理。适合：

- 供应商按次计费（每次调用返回新 IP）；
- 需要高轮换频率的大规模采集；
- 代理自动过期/失效的供应商模式。

## 2. 健康检查与故障降级

`ProxyMiddleware` 内置行为：

| 行为 | 说明 |
|---|---|
| **失败记录**| 请求失败后代理进入 `failed_proxies`，避免立即复用 |
| **阈值剔除**| 失败 ≥ `PROXY_MAX_FAILED_ATTEMPTS` 后不再选用 |
| **自动降级**| 全部代理失败 → 直连（不中断任务） |
| **恢复机制**| 某代理后续请求成功 → 从失败列表移除 |

生产建议：

```python
PROXY_MAX_FAILED_ATTEMPTS = 3 # 网络抖动容忍度
RETRY_HTTP_CODES = [500, 502, 503, 504, 408, 429] # 代理常见错误码走重试
```

> 注意：直连降级会暴露真实 IP。对强反爬目标，建议监控"直连降级"事件
> 并告警（见 [监控与告警](monitoring-alerting.md)），而不是静默继续。

## 3. 生产代理池架构

当单一供应商不够用时，推荐"本地代理池 + 供应商抽象"：

```text
┌────────────┐ PROXY_API_URL ┌─────────────────┐
│ Crawlo │ ─────────────────► │ 代理网关 (自建) │
│ Worker │ │ - 供应商聚合/轮询 │
└────────────┘ │ - 健康检查/剔除 │
 │ - 配额/成本统计 │
 └────────┬────────┘
 │
 ┌────────────┼────────────┐
 ▼ ▼ ▼
 供应商 A 供应商 B 供应商 C
```

网关（如 [proxy_pool](https://github.com/jhao104/proxy_pool) 或自建）
暴露一个统一 API，Crawlo 通过 `PROXY_API_URL` 接入。好处：

- 供应商切换不影响爬虫配置；
- 网关统一做代理健康检查（连通性/匿名度/地区）；
- 成本与用量在网关侧可观测。

## 4. 成本控制

| 场景 | 建议 |
|---|---|
| 按次计费供应商 | 网关缓存代理，设置 TTL（如 60s），避免每次请求都拉新 |
| 并发过大 | 限制 Worker 并发 + 网关限流，防止超额 |
| 代理复用 | 对无状态页面可让网关返回同一代理直到失败（会话粘滞） |
| 监控成本 | 网关记录每次发放/命中/失败，按天汇总费用 |

## 5. 与反爬/动态渲染配合

代理与浏览器下载器组合时注意：

```python
# 浏览器下载器同样支持代理
BROWSER_PROXY = "http://127.0.0.1:7890" # 浏览器走本地代理
PROXY_API_URL = "https://api.proxy-supplier.com/get" # HTTP 下载器走代理池
```

- `CamoufoxDownloader` / `CloakBrowserDownloader` 支持运行时切换代理
 （代理变更后自动重启浏览器上下文）；
- 代理 IP 与浏览器指纹不匹配会被识别——生产上优先给浏览器配
 "住宅代理 + 固定地区"，HTTP 下载器才用高轮换数据中心代理。

## 6. 排障速查

| 现象 | 查什么 | 常见原因 |
|---|---|---|
| 大量 ConnectError | `PROXY_MAX_FAILED_ATTEMPTS` / 供应商状态 | 代理批量失效 |
| 429/403 增多 | 直连降级事件 / IP 复用频率 | 轮换频率不够 / 代理被拉黑 |
| 吞吐骤降 | 代理延迟 + 失败率 | 供应商限流 / 网关瓶颈 |
| 浏览器被识别 | 代理地区与指纹不匹配 | 住宅代理 + 固定地区 |
